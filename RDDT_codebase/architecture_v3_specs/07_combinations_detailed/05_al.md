# AL — 7 rules

Question: **"Is this light-chain amyloidosis?"** AL's rule set is built around one bucket that
matters more than any other: `HEME_CLONAL` (a known or newly-found abnormal plasma-cell/monoclonal
finding). Five of the seven rules pair `HEME_CLONAL` with a different organ; the last two are
special cases (`AL_RULE_06` for the two very specific mucosal findings, `AL_RULE_07` as the
no-known-clone safety funnel).

**Contributing sign IDs** (Tier 1–2, gate-eligible, AL overlay):

| Bucket | Sign IDs |
|---|---|
| HEME_CLONAL | `AL01:T1, AL02:T2` |
| RENAL | `AL04:T1, AL03:T1, AL06:T2` |
| CARDIO | `AL15:T2, AL16:T2, AL17:T2, AL14:T2` |
| NEURO | `AL24:T2` |
| MUCOSAL_CUTANEOUS | `AL08:T1, AL07:T1` |
| AUTONOMIC | *(none reach Tier 1–2 gate-eligible for AL — see edge case below)* |
| GI_HEPATIC | *(none reach Tier 1–2 gate-eligible for AL — see edge case below)* |

## AL_RULE_01 — HEME_CLONAL + RENAL (highest yield)

**Plain question:** Known/suspected clonal disease plus a proteinuric kidney phenotype.
**Requires:** `HEME_CLONAL` Tier 1–2 + `RENAL` Tier 1–2. **Priority:** A. **Route:** `AL_SAFETY_REVIEW`.
**Worked example:** `AL01` (known plasma-cell dyscrasia) + `AL04` (nephrotic-range proteinuria) →
fires — the single strongest AL pattern in the whole rule set.

## AL_RULE_02 — HEME_CLONAL + CARDIO

**Plain question:** Clonal disease plus a cardiac amyloid phenotype.
**Requires:** `HEME_CLONAL` Tier 1–2 + `CARDIO` Tier 1–2. **Priority:** A/B (A when HEME_CLONAL is
Tier 1 via `AL01`; B when it's only Tier 2 via `AL02`, MGUS under surveillance).
**Worked example:** `AL02` (MGUS) + `AL17` (disproportionate NT-proBNP/troponin) → fires at
Priority B.

## AL_RULE_03 — HEME_CLONAL + NEURO

**Plain question:** Clonal disease plus a peripheral neuropathy.
**Requires:** `HEME_CLONAL` Tier 1–2 + `NEURO` Tier 1–2. **Priority:** B.
**Worked example:** `AL01` + `AL24` (symmetric sensorimotor polyneuropathy) → fires.
**Edge case:** `NEURO` has only *one* gate-eligible sign ID for AL (`AL24`) — this rule is
narrower than it looks; any other neuro-flavored AL finding in the source CSV sits below Tier 2 for
this phenotype.

## AL_RULE_04 — HEME_CLONAL + AUTONOMIC

**Plain question:** Clonal disease plus autonomic organ involvement.
**Requires:** `HEME_CLONAL` Tier 1–2 + `AUTONOMIC` Tier 1–2. **Priority:** B.

**Important gap, flagged directly:** as of the current workbook, **no AL sign ID reaches Tier 1–2
gate-eligible status in the AUTONOMIC bucket.** `AL13` (autonomic dysfunction/orthostatic
hypotension) and `AL29` (hypotension/syncope/dizziness) both sit at Tier 3, non-gate-eligible,
under the AL overlay. **This means `AL_RULE_04` cannot currently fire for any patient** — it's a
correctly-specified rule with an empty gate on one side. This isn't a bug to silently fix by
loosening the tier — the workbook's own evidence review judged AL's autonomic findings too weak to
gate on. Flagging it so it isn't mistaken for a working rule when you build the JSON, and so you
can decide deliberately whether to leave it dormant (documented, inert) or revisit the tier
assignment with new evidence.

## AL_RULE_05 — HEME_CLONAL + GI_HEPATIC

**Plain question:** Clonal disease plus GI/hepatic organ involvement.
**Requires:** `HEME_CLONAL` Tier 1–2 + `GI_HEPATIC` Tier 1–2. **Priority:** B.

**Same gap as AL_RULE_04:** no AL sign ID reaches Tier 1–2 gate-eligible in GI_HEPATIC either —
`AL10`, `AL11`, `AL18` all sit at Tier 3. **`AL_RULE_05` is also currently unreachable.** Same
recommendation: leave it in the spec as documented, dormant logic rather than deleting it — the
combination is clinically real (AL literature does describe hepatomegaly/GI dysmotility as organ
involvement), it's just that none of the specific sign IDs in your source CSV were rated strong
enough to gate on.

## AL_RULE_06 — MUCOSAL_CUTANEOUS + any one organ

**Plain question:** A highly specific but rare physical finding (macroglossia or periorbital/pinch
purpura) plus any one confirmed organ finding.
**Requires:** `PAIR_CLASS` — `MUCOSAL_CUTANEOUS` **Tier 1 specifically** + any one of
`RENAL, CARDIO, NEURO, AUTONOMIC, GI_HEPATIC` at Tier 1–2.
**Priority:** A. **Route:** `AL_SAFETY_REVIEW`.
**Worked example:** `AL07` (macroglossia) + `AL03` (new persistent proteinuria) → fires.
**Practical note given the gaps above:** because `AUTONOMIC` and `GI_HEPATIC` have no gate-eligible
AL sign IDs, in practice only `RENAL`, `CARDIO`, or `NEURO` can currently supply the organ side of
this rule.

## AL_RULE_07 — Three or more organ buckets, no known clone required

**Plain question:** Does the patient look AL-shaped across at least three different organ systems,
**even with no known abnormal blood protein on file**?
**Requires:** `COUNT_DISTINCT_BUCKETS`, threshold 3, from the organ set (same buckets as above:
`RENAL, CARDIO, NEURO, AUTONOMIC, GI_HEPATIC, MUCOSAL_CUTANEOUS`). `HEME_CLONAL` is explicitly
**not** required.
**Priority label:** "Possible AL" — again not on the A/B/C scale, deliberately.
**Output route:** `AL_MONOCLONAL_SCREEN` — **not** `AL_SAFETY_REVIEW`. This is the single most
important distinction in the AL rule set: this rule never labels a patient "AL." It only says
"this patient's multisystem pattern is worth a monoclonal-protein work-up," because without
`HEME_CLONAL` evidence, AL cannot be distinguished from AA or from a coincidental combination of
unrelated organ problems.
**Worked example:** `AL03` (RENAL), `AL16` (CARDIO), `AL24` (NEURO) all present, no `AL01`/`AL02`
on file → `AL_RULE_07` fires → route to monoclonal screening, not a diagnosis.
**Practical note given the gaps above:** with `AUTONOMIC` and `GI_HEPATIC` currently unreachable
at gate tier, the realistic pool this rule draws from is `RENAL + CARDIO + NEURO +
MUCOSAL_CUTANEOUS` — a patient needs 3 of those 4 to trigger it today.

## The one thing to remember about all seven AL rules

`AL_RULE_01` through `06` all lead to `AL_SAFETY_REVIEW` — meaning "this looks like AL, work it
up as AL." `AL_RULE_07` alone leads to `AL_MONOCLONAL_SCREEN` — meaning "this looks multisystem,
go find out if it's AL by testing for the clone, don't assume it yet." Those two routes are not
interchangeable and should never be merged into one output category.
